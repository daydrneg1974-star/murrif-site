# murrif.ru

Личная визитка Рифката Муравлева. HTML/CSS/JavaScript без сборки и внешних CDN; форма обращений использует PHP и SMTP. Новая серверная версия подготовлена к согласованию, на SpaceWeb ещё не перенесена.

## Размещение

В публичную папку хостинга нужно загрузить только:

- `index.html`, `privacy.html`, `consent.html`;
- `css/`, `js/`, `api/contact.php`;
- `robots.txt`, `sitemap.xml`;
- `photo-fade.webp`, `photo-square.webp`, `og-image.jpg`;
- `portfolio-stroy.jpg`, `portfolio-zski.jpg` — снимки первых экранов проектов;
- папку `fonts/` вместе с файлами лицензий.

Для SpaceWeb также нужен `.htaccess` из репозитория: он перенаправляет HTTP на HTTPS. Размещать его следует после установки действующего сертификата для домена.

Главная страница должна находиться непосредственно в корне публичной папки, без вложенной папки архива. Репозиторий `.git`, архивы, документацию и тесты публиковать на сайте не нужно.

Хостинг: SpaceWeb. Основной адрес: https://murrif.ru/. `https://www.murrif.ru/` также открывает сайт. HTTP перенаправляется на HTTPS кодом 301 с сохранением пути и параметров.

Установлен бесплатный Let's Encrypt. Хостинг находится в SpaceWeb; управление DNS пока остаётся в Beget, почтовые записи сохранены.

## Индексация

`robots.txt` разрешает обход всем роботам и указывает на `https://murrif.ru/sitemap.xml`.
Карта содержит три существующие страницы с их каноническими HTTPS-адресами без `www`.
При добавлении или удалении страниц обновляйте карту. Не добавляйте в неё ресурсы,
якоря, дубли `/index.html` или технический домен хостинга. Необязательные даты
`lastmod` не указаны, чтобы не сообщать роботам неподтверждённое время изменения.

Смена хостинга при сохранении домена сама по себе не требует заявки на переезд в
Яндекс Вебмастере. Добавление Sitemap и переобход не гарантируют включение в поиск.

Публикация файлов проверена; дальнейшая работа в Вебмастере отложена по просьбе владельца.
Подробности и доказательства: [отчёт об индексации](docs/reports/indexing-2026-11-21.md).

## Форма обращения — версия на согласование

`index.html` отправляет POST в `api/contact.php`. JavaScript показывает результат без перезагрузки; без JavaScript сервер возвращает заполненную форму при ошибке и страницу квитанции при принятии. Прямые контакты сохранены.

Код и PHPMailer 7.2.0 устанавливаются **вне публичной папки**. Нужны подтверждённые настройки PHP/SMTP, закрытый `config.php` и финализация проектов privacy/consent. Пока конфигурация отсутствует или `enabled=false`, форма не сообщает об успешной отправке.

[Пошаговая установка, защита, условия публикации и откат](docs/contact-deployment.md). [Результаты проверки и варианты заголовка](docs/reports/contact-2026-11-24.md).

## Проверки

```sh
composer --working-dir=server install --no-dev --prefer-dist --no-plugins --no-scripts
node --test tests/*.test.cjs
php tests/contact-server.php
```

Node.js 20+, PHP 8.2+ с mbstring/openssl/ctype. Серверные тесты используют подставной транспорт; отдельно проверяется создание MIME-сообщения настоящим PHPMailer без сетевой отправки. Проверки JS охватывают валидацию, состояния отправки, сбои, таймаут, повтор с тем же ключом, меню, контраст, квиз и ресурсы.

Для HTTP/браузерных проверок создать отдельную локальную копию публичных файлов в `dist/`, закрытую часть в `private/murrif-contact/` и выключенный конфиг с `origins=['http://127.0.0.1:4173']`; запустить:

```sh
php -S 127.0.0.1:4173 -t dist tests/router.php
# В другом терминале:
node tests/contact-http.cjs
```

`tests/router.php` — только локальный стенд с подставным транспортом; его запрещено публиковать. Использует тестовую папку `private/http-qa` и проверяет HTTP-контракт. Перед независимым повтором прогона удалить только тестовое состояние в этой папке либо дождаться истечения лимита. Настоящая доставка и настройка хостинга этим не проверяются.
