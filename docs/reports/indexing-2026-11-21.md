# Настройка индексации murrif.ru

Статус: `robots.txt` и `sitemap.xml` опубликованы на SpaceWeb и проверены.
Диагностика аккаунта Яндекс Вебмастера ожидает входа пользователя. Причина
отсутствия сайта по сообщённому поисковому запросу пока не установлена.

## Исходное состояние

- GitHub `main` и чистая локальная копия: `ad23435221a41499cd5fedba7a09ddd0c91014a3`.
- Прочитаны README и отчёт восстановления.
- Главная, политика и согласие: HTTP 200. `robots.txt` и `sitemap.xml`: HTTP 404.
- У трёх страниц есть соответствующие канонические адреса на `https://murrif.ru/`.
- Запрещающие метатеги robots/Yandex и заголовки X-Robots-Tag не обнаружены.

## Изменения

- `robots.txt`: общий `User-agent: *`, разрешение `Allow: /`, ссылка на Sitemap.
- `sitemap.xml`: главная, `/privacy.html`, `/consent.html`. Без дублей `/index.html`,
  адресов www, якорей и технического домена; необязательные даты lastmod не выдумывались.
- README дополнен списком публикуемых файлов и порядком поддержки карты.
- Файлы сохранены через файловый менеджер SpaceWeb только в
  `/home/p/pridomahru/murrif_ru/public_html`.
- Редактор хостинга убрал конечный перевод строки в обоих файлах. Исходники
  приведены к опубликованным байтам после проверки, что это единственное отличие.

Дизайн, тексты, HTML, изображения, шрифты, форма, `.htaccess`, DNS и настройки
соседних проектов не изменялись. Новые услуги, библиотеки и аналитика не добавлялись.

при HTTP-проверках проверялся штатно, без отключения проверки.

## Яндекс Вебмастер: что осталось

Открыт Вебмастер, переход «Добавить сайт» привёл к экрану Яндекс ID без активной
сессии. Страница входа оставлена пользователю. Пароли и коды не запрашивались.

Не выполнено и не объявлено выполненным:

1. Проверка наличия сайта и подтверждённых прав в аккаунте.
2. Проверка главного адреса, статуса URL, последнего обхода и причин исключения.
3. Проверка доступности главной и файлов из инфраструктуры Яндекса.
4. Добавление `https://murrif.ru/sitemap.xml` в раздел «Файлы Sitemap».
5. Отправка `https://murrif.ru/` на переобход.

После входа следует сначала проверить существующие записи сайта и главный адрес,
а затем выполнить нужные действия без дублей. Заявку «Переезд сайта» из-за одной
смены хостинга не отправляли. HTTPS www оставлен как был до получения данных Вебмастера.

Отсутствие robots.txt и Sitemap само по себе не запрещало индексирование. Простой
на прежнем хостинге остаётся гипотезой, а отсутствие результата по одному запросу
не доказывает отсутствие домена во всём индексе.

## Следующая публикация и откат

При изменении списка страниц обновить Sitemap, проверить XML и canonical,
сохранить файлы в GitHub и опубликовать только нужные файлы в каталоге murrif.ru.
Проверить HTTP 200, типы содержимого и совпадение байтов. Документацию и тесты
на публичный сайт не загружать. Для отката именно этого изменения достаточно
убрать два новых файла с хостинга и отменить их добавление отдельным коммитом;
содержимое сайта и текущие правила HTTPS затрагивать не требуется.
