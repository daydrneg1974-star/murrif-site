## Замечания по приоритету

### A1. Средний приоритет — контраст текста после осветления фона

Подписи полей, пояснения формы и мелкий второстепенный текст сохранили прежние серые цвета, хотя фон стал светлее. Это измеряемая проблема читаемости, а не предложение отказаться от утверждённого фона.

| Элемент | Цвет текста / фон | Расчёт контраста | Результат |
| --- | --- | --- | --- |
| Подписи полей, 14 px | `#a1a1aa` / градиент формы `#44444e` → `#3c3c45` | 3.75–4.26:1 | Ниже 4.5:1 во всём диапазоне |
| Пояснения формы, 13 px; обычный текст согласия, 14 px | `#8b8b95` / тот же градиент | 2.85–3.23:1 | Ниже 4.5:1 |
| Текст подвала, 14 px | `#8b8b95` / `#383840` | 3.44:1 | Ниже 4.5:1 |
| Основной светлый текст | `#f4f4f5` / `#383840` | 10.57:1 | Достаточно для обычного текста |

Порог для обычного текста — [WCAG 2.2, SC 1.4.3](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html). Расчёт выполнен по sRGB-яркости цветов CSS; реальные вычисленные стили подтверждены в Chrome. Границы диапазона формы соответствуют её непрозрачным цветам градиента. Цвета ссылок внутри согласия и пояснений отличаются и не включены в расчёт для серого текста. Это адресная проверка контраста, а не сертификация всего сайта по WCAG.

Места: `index.html:57`, `index.html:464`, `index.html:475`, `index.html:493`, `index.html:499`, `index.html:515`; одинаковые серые переменные есть и в `privacy.html:44`, `consent.html:44`.

Рекомендация: сохранить фон `#383840`, осветлить второстепенный текст, отдельно проверить подсказки полей и текст на карточках всех трёх страниц. На контрольных сочетаниях добиться не менее 4.5:1, затем оценить внешний вид в браузере.

Доказательства: [числовой расчёт](vibecoding-audit-2026-11-21/contrast-checks.json), [форма на узком экране](vibecoding-audit-2026-11-21/form-mobile-360.jpg), [настольный вид](vibecoding-audit-2026-11-21/contacts-desktop.jpg).

### A2. Средний приоритет — отсутствуют журналы для диагностики murrif.ru

В SpaceWeb открыт раздел «Статистика и логи» → настройки → выбран именно `murrif.ru`. У элементов `visitLog` и `errorLog` состояние `checked=false`. Показаны пути вне публичной папки: `murrif_ru/access_log` и `murrif_ru/error_log`. Настройки не переключались.

Следствие: проверить ошибки сервера за последние 24 часа по этим журналам не удалось. Это отсутствие диагностических данных, а не подтверждение отсутствия ошибок.

Рекомендация: включить штатный журнал ошибок только для murrif.ru, с ротацией и хранением вне `public_html`. Не добавлять ради этого стороннюю аналитику. Лог посещений не обязателен для предложенного первого шага.

### A3. Средний приоритет — тесты не замечают удаления защиты от обычной отправки формы

В рабочем обработчике `index.html:1170` есть `e.preventDefault()`. Однако в `tests/contact-form.test.cjs` событие содержит пустую функцию `preventDefault()` и её вызов не проверяется.

Для подтверждения в отдельной временной копии удалён только этот вызов из обработчика формы. Все шесть существующих тестов продолжили проходить. Копия удалена; исходники и сайт не изменены. Это подтверждённый пробел тестов. **Утечка данных на рабочем сайте не обнаружена и этим экспериментом не утверждается.**

Рекомендация: проверять отмену стандартной отправки на каждом пути обработчика и отсутствие перехода на URL с полями формы; добавить один браузерный сценарий полного запуска скрипта и валидации. Доставка настоящего письма остаётся отдельной проверкой почтового клиента.

Доказательство: [результат мутационной проверки](vibecoding-audit-2026-11-21/test-audit-mutation.json).

### A4. Низкий приоритет — фокус при закрытии мобильного меню

В Chrome при ширине окна 360 px: открыть меню → дождаться появления ссылок → Tab переводит фокус на «Услуги» → Escape закрывает меню. После скрытия ссылок `document.activeElement` становится `BODY`, а не кнопкой `#burger`. `aria-expanded` корректно меняется на `false`.

Место: `index.html:1131`. Рекомендация: при Escape из открытого меню возвращать фокус на кнопку открытия. Не перехватывать Escape вне меню и не менять обычные переходы по ссылкам.

### A5. Низкий приоритет — опечатка в тексте

`index.html:870`: «Технически сделать сайт может многие». Предлагаемая точечная правка: «Технически сделать сайт могут многие». Во время аудита текст сохранён без изменений.

## Безопасность и зависимости

- Сайт статический. Не обнаружены серверная логика приложения, БД, авторизация пользователей, платежи, API-ключи в конфигурации приложения или внешние JavaScript-библиотеки/CDN. Проверки SQL-инъекций, RLS, ролей и серверных сессий для этого кода неприменимы.
- В коде не найдены `eval`, вставка пользовательского ввода через `innerHTML` или сетевые запросы формы. Ссылки, открываемые в новой вкладке, имеют `rel="noopener"`.
- Поиск секретов охватил 13 достижимых коммитов и 51 уникальный текстовый Git-объект по 8 семействам шаблонов. Кандидатов не найдено. Это собственный ограниченный поиск по шаблонам, **не** Gitleaks/TruffleHog и **не** доказательство отсутствия любых секретов. Удалённая недостижимая история, настройки аккаунта GitHub и двухфакторная защита не проверялись.
- Манифестов пакетных зависимостей и lock-файлов нет. `npm audit` и аналогичный аудит пакетов здесь неприменимы. Пакеты не устанавливались. Node используется только для имеющегося теста и проверки синтаксиса. Состояние ПО самого хостинга и браузеров этим выводом не покрывается.
- `.gitignore` пока не исключает `.env` и приватные ключи. Сейчас таких файлов не найдено; добавить защитные исключения разумно перед появлением серверной интеграции.
- В полученных HTTPS-ответах не представлены CSP, HSTS, `X-Content-Type-Options` и `Referrer-Policy`. Для текущего статического сайта это рекомендация по усилению защиты, не найденная эксплуатация. Внедрение CSP требует учёта встроенных стилей/скриптов; HSTS — отдельного решения по поддоменам. Универсальные правила в `.htaccess` вслепую не предлагать.

## Что остаётся проверить вручную

1. На физическом телефоне открыть сайт, меню, квиз и форму; проверить удобство касаний и читаемость, в том числе с увеличенным системным шрифтом.
2. На устройстве с настроенным почтовым клиентом подготовить письмо из формы, проверить тему/адрес/переносы строк. Настоящее письмо отправлять только при отдельном намерении владельца проверить доставку.
3. На устройстве без настроенного почтового клиента убедиться, что пояснение и запасные контакты понятны.
4. Отдельно проверить Safari/iOS, режим увеличения 200%, скринридер и сценарий с отключённым JavaScript. При аудите Chrome эти режимы не объявлялись пройденными.
5. Подтвердить дату продления домена у регистратора. Юридическое содержание политики/согласия и соответствие обработки данных требованиям законодательства отдельно не оценивались.
